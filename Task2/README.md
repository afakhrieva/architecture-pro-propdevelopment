# Задание 2. Разработка и заполнение проверочного листа для бизнес-систем

## Обоснование выбора разделов проверочного листа

### 1. Управление доступом 
В компании две Active Directory, отсутствует единый реестр учётных записей, нарушен процесс передачи информации 
специалисту ИБ, нет контроля доступа к DWH, API партнёров имеют избыточные права. Это напрямую ведёт к утечкам 
(чужие ФИО в ЛК) и риску несанкционированного доступа.

### 2. Безопасность данных
Основная проблема кейса: классификация данных не реализована, CDC-потоки без маскирования, 
DWH не имеет ограничений доступа, резервное копирование есть, но глубина не указана, нет анонимизации. 
Без этого невозможно использование ML/AI.

### 3. Защита инфраструктуры
Межсетевой экран (firewall) есть, но сегментация сети между сервисами отсутствует (сервисы общаются напрямую). 
Нет IDS/IPS, сканирование уязвимостей не упоминается, антивирусы и EDR – неизвестно.

### 4. Управление инцидентами
Уже произошли инциденты (отображение чужих ФИО), но нет SIEM, плана реагирования, симуляций. 
Специалист ИБ один, информация до него не всегда доходит.

### 5. Специфические аспекты
Компания использует гибридную инфраструктуру (собственный ЦОД + облако), есть мобильные приложения для собственников, 
удалённый доступ клиентов через firewall. MDM и VPN не упоминаются, но требуют проверки. 
Физическая безопасность ЦОД – собственный ЦОД, но нет данных о СКУД.
